Creational pattern

Abstract Factory

Abstract Factory gom việc tạo cả một họ đối tượng luôn đi cùng nhau về một chỗ. Code dùng chúng chỉ chọn factory một lần, và từ đó mọi thứ nó nhận được đều thuộc cùng một họ, không bao giờ bị lẫn.

Bài toán

Trang thanh toán của bạn tích hợp hai nhà cung cấp. Với nhà cung cấp nào cũng cần đủ ba thành phần, gồm cổng thanh toán để thu tiền, dịch vụ hoàn tiền, và bộ kiểm chữ ký cho webhook mà nhà cung cấp gửi về khi tiền đã vào tài khoản.

Thành phầnNhà cung cấp ANhà cung cấp B
Cổng thanh toánKý webhook kiểu a1: bằng khoá của AKý webhook kiểu v2= bằng khoá của B
Hoàn tiềnTrả mã HT-A-…Trả mã HT-B-…
Kiểm chữ kýChỉ nhận chữ ký a1: của AChỉ nhận chữ ký v2= của B

Ba thành phần của cùng một nhà cung cấp dùng chung khoá bí mật và kiểu chữ ký, nên chúng chỉ chạy đúng khi đi cùng nhau. Nếu cổng thanh toán là của A mà bộ kiểm chữ ký lại là của B, mọi webhook từ A sẽ bị từ chối, và những đơn hàng đã thu tiền sẽ không bao giờ được xác nhận.

Khi chưa có Abstract Factory

Cách làm thường gặp là để mỗi chỗ tự đọc cấu hình rồi tự rẽ nhánh theo nhà cung cấp:

before.pypython3 before.py
"""Trước khi có Abstract Factory: mỗi chỗ tự chọn nhà cung cấp theo một dòng cấu hình riêng.

Chạy: python3 before.py
"""
import hashlib
import hmac

SECRETS = {"A": b"bi-mat-cua-a", "B": b"bi-mat-cua-b"}
PREFIX = {"A": "a1:", "B": "v2="}

# Ba dòng cấu hình đọc ở ba chỗ khác nhau. Lần chuyển sang A vừa rồi còn sót dòng webhook.
SETTINGS = {"payment": "A", "refund": "A", "webhook": "B"}


def sign(provider: str, body: str) -> str:
    return PREFIX[provider] + hmac.new(SECRETS[provider], body.encode(), hashlib.sha256).hexdigest()[:8]


def vnd(amount: int) -> str:
    return f"{amount:,}".replace(",", ".") + " ₫"


def charge(order: str, amount: int) -> tuple[str, str]:
    body = f"{order}|{amount}"
    if SETTINGS["payment"] == "A":
        return body, sign("A", body)
    elif SETTINGS["payment"] == "B":
        return body, sign("B", body)
    raise ValueError("nhà cung cấp lạ")


def verify(body: str, signature: str) -> bool:
    if SETTINGS["webhook"] == "A":
        return signature == sign("A", body)
    elif SETTINGS["webhook"] == "B":
        return signature == sign("B", body)
    raise ValueError("nhà cung cấp lạ")


def refund(order: str, amount: int) -> str:
    if SETTINGS["refund"] == "A":
        return f"HT-A-{order[-4:]}"
    elif SETTINGS["refund"] == "B":
        return f"HT-B-{order[-4:]}"
    raise ValueError("nhà cung cấp lạ")


body, signature = charge("DH-3001", 1250000)
print(f"Thu {vnd(1250000)} qua {SETTINGS['payment']}, webhook {signature}")
print(f"Kiểm webhook bằng bộ của {SETTINGS['webhook']}: {'hợp lệ' if verify(body, signature) else 'bị từ chối'}")
print(f"Hoàn {vnd(250000)} qua {SETTINGS['refund']}, mã {refund('DH-3001', 250000)}")

// Trước khi có Abstract Factory: mỗi chỗ tự chọn nhà cung cấp theo một dòng cấu hình riêng.
// Chạy: node before.ts
import { createHmac } from "node:crypto";

const SECRETS: Record<string, string> = { A: "bi-mat-cua-a", B: "bi-mat-cua-b" };
const PREFIX: Record<string, string> = { A: "a1:", B: "v2=" };

// Ba dòng cấu hình đọc ở ba chỗ khác nhau. Lần chuyển sang A vừa rồi còn sót dòng webhook.
const SETTINGS = { payment: "A", refund: "A", webhook: "B" };

const sign = (provider: string, body: string) =>
  PREFIX[provider] + createHmac("sha256", SECRETS[provider]).update(body).digest("hex").slice(0, 8);
const vnd = (amount: number) => String(amount).replace(/\B(?=(\d{3})+(?!\d))/g, ".") + " ₫";

function charge(order: string, amount: number): [string, string] {
  const body = `${order}|${amount}`;
  if (SETTINGS.payment === "A") return [body, sign("A", body)];
  else if (SETTINGS.payment === "B") return [body, sign("B", body)];
  throw new Error("nhà cung cấp lạ");
}

function verify(body: string, signature: string): boolean {
  if (SETTINGS.webhook === "A") return signature === sign("A", body);
  else if (SETTINGS.webhook === "B") return signature === sign("B", body);
  throw new Error("nhà cung cấp lạ");
}

function refund(order: string, amount: number): string {
  if (SETTINGS.refund === "A") return `HT-A-${order.slice(-4)}`;
  else if (SETTINGS.refund === "B") return `HT-B-${order.slice(-4)}`;
  throw new Error("nhà cung cấp lạ");
}

const [body, signature] = charge("DH-3001", 1250000);
console.log(`Thu ${vnd(1250000)} qua ${SETTINGS.payment}, webhook ${signature}`);
console.log(`Kiểm webhook bằng bộ của ${SETTINGS.webhook}: ${verify(body, signature) ? "hợp lệ" : "bị từ chối"}`);
console.log(`Hoàn ${vnd(250000)} qua ${SETTINGS.refund}, mã ${refund("DH-3001", 250000)}`);

Chạy thử, ta được kết quả này.

Thu 1.250.000 ₫ qua A, webhook a1:9e2d13c1
Kiểm webhook bằng bộ của B: bị từ chối
Hoàn 250.000 ₫ qua A, mã HT-A-3001
  • Lựa chọn nhà cung cấp bị rải ra nhiều nơi. Ba hàm, mỗi hàm tự đọc một dòng cấu hình và tự rẽ nhánh, nên không có chỗ nào bảo đảm cả ba cùng chọn một nhà cung cấp.
  • Một bộ lẫn rất dễ lọt vào production. Lần chuyển sang A vừa rồi còn sót dòng cấu hình webhook, nên tiền đã thu mà webhook bị từ chối, đúng như kết quả ở trên.
  • Thêm nhà cung cấp là sửa nhiều chỗ. Nhà cung cấp thứ ba đồng nghĩa với một nhánh mới trong cả ba hàm, và chỉ cần sót một hàm là lỗi.

Lời giải

Ta định nghĩa một interface cho cả bộ, gọi là Abstract Factory. Ở đây đó là PaymentKitFactory với ba phương thức create_gateway(), create_refunds() và create_verifier(). Mỗi nhà cung cấp có một factory cụ thể, ProviderAFactory hoặc ProviderBFactory, và factory nào cũng chỉ biết tạo đúng ba thành phần của họ mình.

Trang thanh toán, tức Client, nhận một factory qua constructor rồi lấy cả ba thành phần từ đó. Nó không biết đang làm việc với nhà cung cấp nào, và cũng không có cách nào tự ghép thành phần của hai nhà cung cấp với nhau.

abstract-factory.pypython3 abstract-factory.py
"""Abstract Factory: mỗi nhà cung cấp thanh toán là một factory tạo ra trọn bộ ba thành phần đi cùng nhau.

Chạy: python3 abstract-factory.py
"""
import hashlib
import hmac
from dataclasses import dataclass
from typing import Protocol


@dataclass(frozen=True)
class Webhook:
    body: str
    signature: str


def sign(secret: bytes, body: str) -> str:
    return hmac.new(secret, body.encode(), hashlib.sha256).hexdigest()[:8]


def vnd(amount: int) -> str:
    return f"{amount:,}".replace(",", ".") + " ₫"


# Ba sản phẩm trừu tượng: những gì trang thanh toán cần, không gắn với nhà cung cấp nào.
class Gateway(Protocol):
    def charge(self, order: str, amount: int) -> Webhook: ...


class Refunds(Protocol):
    def refund(self, order: str, amount: int) -> str: ...


class WebhookVerifier(Protocol):
    def verify(self, hook: Webhook) -> bool: ...


# Họ A: ba lớp dùng chung khoá bí mật và kiểu chữ ký "a1:" của nhà cung cấp A.
SECRET_A = b"bi-mat-cua-a"


class GatewayA:
    def charge(self, order: str, amount: int) -> Webhook:
        body = f"{order}|{amount}"
        return Webhook(body, "a1:" + sign(SECRET_A, body))


class RefundsA:
    def refund(self, order: str, amount: int) -> str:
        return f"HT-A-{order[-4:]}"


class VerifierA:
    def verify(self, hook: Webhook) -> bool:
        return hook.signature == "a1:" + sign(SECRET_A, hook.body)


# Họ B: khoá và kiểu chữ ký "v2=" riêng của nhà cung cấp B.
SECRET_B = b"bi-mat-cua-b"


class GatewayB:
    def charge(self, order: str, amount: int) -> Webhook:
        body = f"{order}|{amount}"
        return Webhook(body, "v2=" + sign(SECRET_B, body))


class RefundsB:
    def refund(self, order: str, amount: int) -> str:
        return f"HT-B-{order[-4:]}"


class VerifierB:
    def verify(self, hook: Webhook) -> bool:
        return hook.signature == "v2=" + sign(SECRET_B, hook.body)


# Abstract Factory: một interface tạo ra cả bộ.
class PaymentKitFactory(Protocol):
    def create_gateway(self) -> Gateway: ...
    def create_refunds(self) -> Refunds: ...
    def create_verifier(self) -> WebhookVerifier: ...


# Mỗi factory cụ thể chỉ biết tạo đúng họ của mình, nên không thể trả về một bộ lẫn.
class ProviderAFactory:
    def create_gateway(self) -> Gateway:
        return GatewayA()

    def create_refunds(self) -> Refunds:
        return RefundsA()

    def create_verifier(self) -> WebhookVerifier:
        return VerifierA()


class ProviderBFactory:
    def create_gateway(self) -> Gateway:
        return GatewayB()

    def create_refunds(self) -> Refunds:
        return RefundsB()

    def create_verifier(self) -> WebhookVerifier:
        return VerifierB()


# Client: nhận một factory và không biết đó là nhà cung cấp nào.
class Checkout:
    def __init__(self, factory: PaymentKitFactory) -> None:
        self.gateway = factory.create_gateway()
        self.refunds = factory.create_refunds()
        self.verifier = factory.create_verifier()

    def pay_then_refund(self, order: str, amount: int, back: int) -> str:
        hook = self.gateway.charge(order, amount)
        status = "hợp lệ" if self.verifier.verify(hook) else "bị từ chối"
        code = self.refunds.refund(order, back)
        return f"thu {vnd(amount)}, webhook {hook.signature} {status}, hoàn {vnd(back)} mã {code}"


for name, factory in [("Bộ A", ProviderAFactory()), ("Bộ B", ProviderBFactory())]:
    print(f"{name}: {Checkout(factory).pay_then_refund('DH-3001', 1250000, 250000)}")
abstract-factory.tsnode abstract-factory.ts
// Abstract Factory: mỗi nhà cung cấp thanh toán là một factory tạo ra trọn bộ ba thành phần đi cùng nhau.
// Chạy: node abstract-factory.ts   (Node 22.18 trở lên chạy thẳng TypeScript)
import { createHmac } from "node:crypto";

interface Webhook {
  body: string;
  signature: string;
}

const sign = (secret: string, body: string) => createHmac("sha256", secret).update(body).digest("hex").slice(0, 8);
const vnd = (amount: number) => String(amount).replace(/\B(?=(\d{3})+(?!\d))/g, ".") + " ₫";

// Ba sản phẩm trừu tượng: những gì trang thanh toán cần, không gắn với nhà cung cấp nào.
interface Gateway {
  charge(order: string, amount: number): Webhook;
}

interface Refunds {
  refund(order: string, amount: number): string;
}

interface WebhookVerifier {
  verify(hook: Webhook): boolean;
}

// Họ A: ba lớp dùng chung khoá bí mật và kiểu chữ ký "a1:" của nhà cung cấp A.
const SECRET_A = "bi-mat-cua-a";

class GatewayA implements Gateway {
  charge(order: string, amount: number): Webhook {
    const body = `${order}|${amount}`;
    return { body, signature: "a1:" + sign(SECRET_A, body) };
  }
}

class RefundsA implements Refunds {
  refund(order: string, amount: number): string {
    return `HT-A-${order.slice(-4)}`;
  }
}

class VerifierA implements WebhookVerifier {
  verify(hook: Webhook): boolean {
    return hook.signature === "a1:" + sign(SECRET_A, hook.body);
  }
}

// Họ B: khoá và kiểu chữ ký "v2=" riêng của nhà cung cấp B.
const SECRET_B = "bi-mat-cua-b";

class GatewayB implements Gateway {
  charge(order: string, amount: number): Webhook {
    const body = `${order}|${amount}`;
    return { body, signature: "v2=" + sign(SECRET_B, body) };
  }
}

class RefundsB implements Refunds {
  refund(order: string, amount: number): string {
    return `HT-B-${order.slice(-4)}`;
  }
}

class VerifierB implements WebhookVerifier {
  verify(hook: Webhook): boolean {
    return hook.signature === "v2=" + sign(SECRET_B, hook.body);
  }
}

// Abstract Factory: một interface tạo ra cả bộ.
interface PaymentKitFactory {
  createGateway(): Gateway;
  createRefunds(): Refunds;
  createVerifier(): WebhookVerifier;
}

// Mỗi factory cụ thể chỉ biết tạo đúng họ của mình, nên không thể trả về một bộ lẫn.
class ProviderAFactory implements PaymentKitFactory {
  createGateway(): Gateway {
    return new GatewayA();
  }
  createRefunds(): Refunds {
    return new RefundsA();
  }
  createVerifier(): WebhookVerifier {
    return new VerifierA();
  }
}

class ProviderBFactory implements PaymentKitFactory {
  createGateway(): Gateway {
    return new GatewayB();
  }
  createRefunds(): Refunds {
    return new RefundsB();
  }
  createVerifier(): WebhookVerifier {
    return new VerifierB();
  }
}

// Client: nhận một factory và không biết đó là nhà cung cấp nào.
class Checkout {
  private readonly gateway: Gateway;
  private readonly refunds: Refunds;
  private readonly verifier: WebhookVerifier;

  constructor(factory: PaymentKitFactory) {
    this.gateway = factory.createGateway();
    this.refunds = factory.createRefunds();
    this.verifier = factory.createVerifier();
  }

  payThenRefund(order: string, amount: number, back: number): string {
    const hook = this.gateway.charge(order, amount);
    const status = this.verifier.verify(hook) ? "hợp lệ" : "bị từ chối";
    const code = this.refunds.refund(order, back);
    return `thu ${vnd(amount)}, webhook ${hook.signature} ${status}, hoàn ${vnd(back)} mã ${code}`;
  }
}

const factories: [string, PaymentKitFactory][] = [["Bộ A", new ProviderAFactory()], ["Bộ B", new ProviderBFactory()]];
for (const [name, factory] of factories) {
  console.log(`${name}: ${new Checkout(factory).payThenRefund("DH-3001", 1250000, 250000)}`);
}

Bộ A: thu 1.250.000 ₫, webhook a1:9e2d13c1 hợp lệ, hoàn 250.000 ₫ mã HT-A-3001
Bộ B: thu 1.250.000 ₫, webhook v2=c5881383 hợp lệ, hoàn 250.000 ₫ mã HT-B-3001

Đổi nhà cung cấp giờ chỉ là đổi factory truyền vào Checkout, và với factory nào thì webhook cũng được chính bộ kiểm của cùng nhà cung cấp chấp nhận.

Các vai trò

Vai tròTrong hìnhTrong code

Concrete FactoryThanh chọn bộ đặt ở A hoặc ở BProviderAFactory, ProviderBFactory

Concrete ProductChi tiết khớp tròn của A và chi tiết khớp vuông của BGatewayA, VerifierB và các lớp còn lại

Khi nào dùng

  • Khi có nhiều họ đối tượng buộc phải dùng cùng nhau. Ví dụ là các nhà cung cấp thanh toán, bộ giao diện sáng và tối, hay driver cho từng loại cơ sở dữ liệu với kết nối, câu lệnh và cách thoát chuỗi riêng.
  • Khi muốn đổi cả họ chỉ bằng một lựa chọn. Bạn chọn factory lúc khởi động theo cấu hình, còn phần còn lại của ứng dụng không cần biết đã chọn gì.
  • Khi muốn thay cả họ bằng bản giả lúc test. Một FakePaymentFactory trả về ba bản giả đi cùng nhau, nên test không phải ghép từng bản giả bằng tay.

Khi nào không nên

  • Khi chỉ cần tạo một loại đối tượng. Một hàm tạo hay Factory Method là đủ, thêm cả một factory chỉ làm code dài hơn.
  • Khi các thành phần không thật sự phụ thuộc nhau. Nếu chúng ghép tuỳ ý mà vẫn chạy đúng, buộc chúng vào một họ chỉ thêm ràng buộc thừa.
  • Khi các loại sản phẩm còn thay đổi liên tục. Mỗi loại mới buộc bạn sửa interface factory và mọi factory cụ thể cùng lúc.

Dễ nhầm với

  • Factory Method để lớp con quyết định tạo một sản phẩm. Abstract Factory là một đối tượng tạo cả một họ sản phẩm, và mỗi phương thức tạo bên trong nó thường chính là một factory method.
  • Builder dựng một đối tượng phức tạp qua nhiều bước rồi mới trả về. Abstract Factory trả về từng sản phẩm ngay, và điều nó lo là các sản phẩm cùng họ với nhau.
  • Strategy đổi một thuật toán duy nhất. Abstract Factory đổi cả một nhóm đối tượng cần đi cùng nhau.

Ghi chú khi triển khai

  • Chọn factory ở đúng một chỗ, lúc khởi động. Sau đó truyền nó vào nơi cần qua constructor hay DI, đừng để code nghiệp vụ tự đọc cấu hình rồi tự tạo factory.
  • Factory là nơi tự nhiên để giữ tài nguyên dùng chung của cả họ. Khoá bí mật, HTTP client hay cấu hình riêng của một nhà cung cấp có thể nằm trong factory, rồi được truyền cho từng sản phẩm nó tạo ra.
  • Hãy để trình kiểm kiểu làm việc giúp bạn. Khai báo factory bằng Protocol trong Python hay interface trong TypeScript, thì factory nào thiếu phương thức sẽ bị báo lỗi ngay.
  • Thêm nhà cung cấp là thêm code, không phải sửa code. Nhà cung cấp mới cần một factory và ba lớp sản phẩm của nó, còn Checkout giữ nguyên.

Kiểm tra nhanh

Sáu câu hỏi ngắn để xem bạn đã nắm Abstract Factory tới đâu. Chọn một đáp án, lời giải thích sẽ hiện ngay bên dưới.

  1. Câu 1 Ứng dụng có giao diện sáng và giao diện tối. Mỗi giao diện có nút bấm, ô nhập và hộp thoại riêng, và đặt một nút của giao diện sáng vào hộp thoại tối trông rất lỗi. Pattern nào hợp nhất để tạo các thành phần này?

    Đây là một họ đối tượng phải đi cùng nhau, nên một factory cho giao diện sáng và một factory cho giao diện tối sẽ bảo đảm mọi thành phần cùng một kiểu. Singleton chỉ giới hạn số thể hiện, còn Decorator thêm hành vi chứ không lo chuyện các thành phần có hợp nhau hay không.

  2. Câu 2 Trong ví dụ thanh toán, lớp nào là một Concrete Factory?

    ProviderBFactory tạo ra đúng ba thành phần của nhà cung cấp B, nên nó là một Concrete Factory. PaymentKitFactory là interface chung, Checkout là Client, còn VerifierB là một sản phẩm do factory tạo ra.

  3. Câu 3 Bản code cũ đọc cấu hình payment: A, refund: A và webhook: B. Khi chạy, chuyện gì xảy ra?

    Không có gì trong code cũ kiểm tra ba dòng cấu hình có cùng một nhà cung cấp hay không, nên nó vẫn chạy và chỉ hỏng ở bước kiểm webhook. Chữ ký kiểu a1: của A không bao giờ khớp với bộ kiểm của B, nên khách đã trả tiền mà đơn hàng không được xác nhận.

  4. Câu 4 Trong hình, khi kéo thanh chọn bộ từ A sang B thì điều gì xảy ra?

    Thanh chọn bộ cắm chốt qua cả ba giá, nên chọn một lần là đổi trọn cả họ, giống như truyền một factory khác vào Checkout. Chỉ khi nhấc thanh ra, như ở bước bộ lẫn, các giá mới có thể lệch nhau.

  5. Câu 5 Điểm khác nhau chính giữa Abstract Factory và Factory Method là gì?

    Factory Method xoay quanh một phương thức tạo được lớp con ghi đè. Abstract Factory gom nhiều phương thức tạo vào một đối tượng để các sản phẩm luôn cùng họ, và mỗi phương thức trong đó thường chính là một factory method.

  6. Câu 6 Bạn muốn mọi nhà cung cấp có thêm dịch vụ đối soát. Với Abstract Factory, bạn phải sửa những gì?

    Thêm một loại sản phẩm nghĩa là interface factory có thêm một phương thức, và factory cụ thể nào cũng phải viết nó. Đây là cái giá của pattern này, nên nó hợp nhất khi các loại sản phẩm đã ổn định và chỉ có họ mới được thêm vào.

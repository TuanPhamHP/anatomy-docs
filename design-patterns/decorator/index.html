Structural pattern

Decorator

Decorator bọc một đối tượng trong một đối tượng khác có cùng interface, để thêm hành vi như ghi log, cache hay thử lại mà không phải sửa lớp gốc. Lớp bọc nhận lời gọi, làm phần việc của mình rồi chuyển tiếp xuống đối tượng bên trong. Vì lớp bọc cũng mang đúng interface đó, bạn có thể chồng nhiều lớp lên nhau theo thứ tự nào cũng được.

Bài toán

Hệ thống bán hàng cần tỷ giá để quy đổi giá ngoại tệ sang VND. Lớp HttpRateSource gọi API tỷ giá của nhà cung cấp qua phương thức get_rate(pair). Khi chạy thật, ta cần thêm ba thứ nữa:

Cần thêmVì saoKhi nào không cần
Ghi log mỗi lần gọi APIĐể biết lúc nào API chậm hay lỗiTest đơn vị không cần log
Thử lại khi hết thời gian chờAPI bên ngoài thỉnh thoảng lỗi thoáng quaJob chạy nền đã tự thử lại theo lịch riêng

Mỗi nơi dùng lại cần một tổ hợp khác nhau, trong khi lớp HttpRateSource chỉ nên làm đúng một điều là gọi API.

Khi chưa có Decorator

Cách làm hay gặp là nhét cả ba thứ vào client gọi API rồi bật tắt bằng cờ:

"""Khi chưa có Decorator: log, thử lại, cache viết thẳng vào client gọi API, bật tắt bằng cờ."""


class RateClient:
    def __init__(self, log: bool = False, retries: int = 1, cache: bool = False, fails: int = 0) -> None:
        self.log = log
        self.retries = retries
        self.cache = cache
        self.calls = 0
        self._fails = fails  # giả lập: API lỗi vài lần đầu
        self._saved: dict[str, int] = {}

    def get_rate(self, pair: str) -> int:
        if self.cache and pair in self._saved:
            return self._saved[pair]
        for attempt in range(1, self.retries + 1):
            try:
                self.calls += 1  # gọi API thật
                if self.calls <= self._fails:
                    raise TimeoutError("hết thời gian chờ")
                rate = 25380
                if self.log:
                    print(f"[log] get_rate({pair}) -> {rate}")
                if self.cache:
                    self._saved[pair] = rate
                return rate
            except TimeoutError as error:
                if self.log:
                    print(f"[log] get_rate({pair}) -> lỗi: {error}")
                if attempt == self.retries:
                    raise
        raise AssertionError("không tới được đây")


if __name__ == "__main__":
    client = RateClient(log=True, retries=3, cache=True)
    client.get_rate("USD/VND")
    print(client.get_rate("USD/VND"), "| gọi API:", client.calls)

// Khi chưa có Decorator: log, thử lại, cache viết thẳng vào client gọi API, bật tắt bằng cờ.

class RateClient {
  calls = 0;
  private readonly saved = new Map<string, number>();
  private readonly opts: { log?: boolean; retries?: number; cache?: boolean; fails?: number };

  constructor(opts: { log?: boolean; retries?: number; cache?: boolean; fails?: number } = {}) {
    this.opts = opts;
  }

  getRate(pair: string): number {
    const { log = false, retries = 1, cache = false, fails = 0 } = this.opts;
    const saved = this.saved.get(pair);
    if (cache && saved !== undefined) return saved;
    for (let attempt = 1; ; attempt++) {
      try {
        this.calls += 1; // gọi API thật
        if (this.calls <= fails) throw new Error("hết thời gian chờ"); // giả lập: API lỗi vài lần đầu
        const rate = 25380;
        if (log) console.log(`[log] get_rate(${pair}) -> ${rate}`);
        if (cache) this.saved.set(pair, rate);
        return rate;
      } catch (error) {
        if (log) console.log(`[log] get_rate(${pair}) -> lỗi: ${(error as Error).message}`);
        if (attempt === retries) throw error;
      }
    }
  }
}

const client = new RateClient({ log: true, retries: 3, cache: true });
client.getRate("USD/VND");
console.log(client.getRate("USD/VND"), "| gọi API:", client.calls);
  • Mỗi tính năng mới lại bắt sửa lớp gốc. Muốn đo thời gian hay giới hạn tần suất gọi, bạn lại phải mở get_rate() ra sửa, và hàm cứ phình ra theo số cờ.
  • Các phần dính chặt vào nhau. Log nằm giữa vòng thử lại, cache lại nằm giữa log, nên sửa chỗ này rất dễ làm hỏng chỗ kia. Thứ tự giữa chúng cũng bị đóng cứng trong code.
  • Không dùng lại được. Nếu có thêm một nhà cung cấp tỷ giá thứ hai cũng cần log, thử lại và cache như vậy, bạn phải chép lại cả hàm.
  • Dùng kế thừa cũng không khá hơn. Các lớp như LoggedClient, CachedLoggedClient, CachedRetryingLoggedClient sẽ tăng lên theo số tổ hợp.

Lời giải

Ta giữ một interface chung là RateSource với phương thức get_rate(pair), đóng vai Component. HttpRateSource là phần lõi thật, gọi là Concrete component.

Mỗi tính năng thêm vào là một lớp bọc riêng, tức một Decorator. Lớp bọc nhận một RateSource qua constructor, và bản thân nó cũng là một RateSource. Trong get_rate, nó làm phần của mình rồi gọi xuống đối tượng bên trong. Phần code sử dụng đóng vai Client, chỉ cầm một RateSource và không biết bên dưới có bao nhiêu lớp.

decorator.pypython3 decorator.py
"""Decorator: thêm log, thử lại, cache quanh một nguồn tỷ giá mà không sửa nó.

Chạy: python3 decorator.py
"""
from typing import Protocol


# Component: interface chung. Lõi và mọi lớp bọc đều có đúng hàm này.
class RateSource(Protocol):
    def get_rate(self, pair: str) -> int: ...


# Concrete component: gọi API tỷ giá thật (ở đây giả lập: lỗi `fails` lần đầu).
class HttpRateSource:
    def __init__(self, fails: int = 0) -> None:
        self.calls = 0
        self._fails = fails

    def get_rate(self, pair: str) -> int:
        self.calls += 1
        if self.calls <= self._fails:
            raise TimeoutError("hết thời gian chờ")
        return 25380


# Decorator: giữ một RateSource bên trong, và chính nó cũng là một RateSource.
class LoggingSource:
    def __init__(self, inner: RateSource) -> None:
        self._inner = inner
        self.lines = 0

    def get_rate(self, pair: str) -> int:
        try:
            rate = self._inner.get_rate(pair)
        except TimeoutError as error:
            self._log(f"get_rate({pair}) -> lỗi: {error}")
            raise
        self._log(f"get_rate({pair}) -> {vnd(rate)}")
        return rate

    def _log(self, text: str) -> None:
        self.lines += 1
        print(f"   [log] {text}")


class RetrySource:
    def __init__(self, inner: RateSource, tries: int = 3) -> None:
        self._inner = inner
        self._tries = tries
        self.last_tries = 0

    def get_rate(self, pair: str) -> int:
        for attempt in range(1, self._tries + 1):
            self.last_tries = attempt
            try:
                return self._inner.get_rate(pair)
            except TimeoutError:
                if attempt == self._tries:
                    raise
                print(f"   [retry] thử lại, lần {attempt + 1}/{self._tries}")
        raise AssertionError("không tới được đây")


class CachingSource:
    def __init__(self, inner: RateSource) -> None:
        self._inner = inner
        self._saved: dict[str, int] = {}
        self.hits = 0

    def get_rate(self, pair: str) -> int:
        if pair in self._saved:
            self.hits += 1
            print(f"   [cache] trúng: {pair}")
            return self._saved[pair]
        rate = self._inner.get_rate(pair)
        self._saved[pair] = rate
        return rate


def vnd(n: int) -> str:
    return f"{n:,}".replace(",", ".")


def name_of(source: RateSource) -> str:
    inner = getattr(source, "_inner", None)
    return type(source).__name__ + (f"({name_of(inner)})" if inner else "")


# Client: chỉ biết RateSource, không biết bên dưới có mấy lớp bọc.
def show(n: int, source: RateSource, api: HttpRateSource, calls: int = 1, note: str = "", **probes) -> None:
    print(f"{n}. {name_of(source)}{note}")
    for _ in range(calls):
        rate = source.get_rate("USD/VND")
    parts = [f"USD/VND = {vnd(rate)} ₫" + (f" (x{calls})" if calls > 1 else "")]
    if "cache" in probes:
        parts.append(f"cache trúng: {probes['cache'].hits}")
    if "retry" in probes:
        parts.append(f"lần thử: {probes['retry'].last_tries}")
    if "log" in probes:
        parts.append(f"log: {probes['log'].lines}")
    parts.append(f"gọi API: {api.calls}")
    print("   " + " | ".join(parts))


if __name__ == "__main__":
    # 1. Lõi trần.
    api = HttpRateSource()
    show(1, api, api)

    # 2. Bọc log quanh lõi.
    api = HttpRateSource()
    log = LoggingSource(api)
    show(2, log, api, log=log)

    # 3. Bọc thêm thử lại; API lỗi lần đầu.
    api = HttpRateSource(fails=1)
    log = LoggingSource(api)
    retry = RetrySource(log)
    show(3, retry, api, note=", API lỗi lần đầu", log=log, retry=retry)

    # 4. Bọc thêm cache ngoài cùng; gọi hai lần cùng một cặp tiền.
    api = HttpRateSource()
    log = LoggingSource(api)
    retry = RetrySource(log)
    cache = CachingSource(retry)
    show(4, cache, api, calls=2, note=", gọi 2 lần", log=log, retry=retry, cache=cache)

// Decorator: thêm log, thử lại, cache quanh một nguồn tỷ giá mà không sửa nó.
// Chạy: node decorator.ts   (Node 22.18 trở lên chạy thẳng TypeScript)

// Component: interface chung. Lõi và mọi lớp bọc đều có đúng hàm này.
interface RateSource {
  getRate(pair: string): number;
}

class TimeoutError extends Error {}

// Concrete component: gọi API tỷ giá thật (ở đây giả lập: lỗi `fails` lần đầu).
class HttpRateSource implements RateSource {
  calls = 0;
  private readonly fails: number;

  constructor(fails = 0) {
    this.fails = fails;
  }

  getRate(pair: string): number {
    this.calls += 1;
    if (this.calls <= this.fails) throw new TimeoutError("hết thời gian chờ");
    return 25380;
  }
}

const vnd = (n: number) => String(n).replace(/\B(?=(\d{3})+(?!\d))/g, ".");

// Decorator: giữ một RateSource bên trong, và chính nó cũng là một RateSource.
class LoggingSource implements RateSource {
  readonly inner: RateSource;
  lines = 0;

  constructor(inner: RateSource) {
    this.inner = inner;
  }

  getRate(pair: string): number {
    let rate: number;
    try {
      rate = this.inner.getRate(pair);
    } catch (error) {
      this.log(`get_rate(${pair}) -> lỗi: ${(error as Error).message}`);
      throw error;
    }
    this.log(`get_rate(${pair}) -> ${vnd(rate)}`);
    return rate;
  }

  private log(text: string) {
    this.lines += 1;
    console.log(`   [log] ${text}`);
  }
}

class RetrySource implements RateSource {
  readonly inner: RateSource;
  private readonly tries: number;
  lastTries = 0;

  constructor(inner: RateSource, tries = 3) {
    this.inner = inner;
    this.tries = tries;
  }

  getRate(pair: string): number {
    for (let attempt = 1; ; attempt++) {
      this.lastTries = attempt;
      try {
        return this.inner.getRate(pair);
      } catch (error) {
        if (!(error instanceof TimeoutError) || attempt === this.tries) throw error;
        console.log(`   [retry] thử lại, lần ${attempt + 1}/${this.tries}`);
      }
    }
  }
}

class CachingSource implements RateSource {
  readonly inner: RateSource;
  private readonly saved = new Map<string, number>();
  hits = 0;

  constructor(inner: RateSource) {
    this.inner = inner;
  }

  getRate(pair: string): number {
    const saved = this.saved.get(pair);
    if (saved !== undefined) {
      this.hits += 1;
      console.log(`   [cache] trúng: ${pair}`);
      return saved;
    }
    const rate = this.inner.getRate(pair);
    this.saved.set(pair, rate);
    return rate;
  }
}

const nameOf = (source: RateSource): string => {
  const inner = (source as { inner?: RateSource }).inner;
  return source.constructor.name + (inner ? `(${nameOf(inner)})` : "");
};

// Client: chỉ biết RateSource, không biết bên dưới có mấy lớp bọc.
function show(n: number, source: RateSource, api: HttpRateSource, opts: { calls?: number; note?: string; log?: LoggingSource; retry?: RetrySource; cache?: CachingSource } = {}) {
  const calls = opts.calls ?? 1;
  console.log(`${n}. ${nameOf(source)}${opts.note ?? ""}`);
  let rate = 0;
  for (let i = 0; i < calls; i++) rate = source.getRate("USD/VND");
  const parts = [`USD/VND = ${vnd(rate)} ₫${calls > 1 ? ` (x${calls})` : ""}`];
  if (opts.cache) parts.push(`cache trúng: ${opts.cache.hits}`);
  if (opts.retry) parts.push(`lần thử: ${opts.retry.lastTries}`);
  if (opts.log) parts.push(`log: ${opts.log.lines}`);
  parts.push(`gọi API: ${api.calls}`);
  console.log(`   ${parts.join(" | ")}`);
}

// 1. Lõi trần.
{
  const api = new HttpRateSource();
  show(1, api, api);
}
// 2. Bọc log quanh lõi.
{
  const api = new HttpRateSource();
  const log = new LoggingSource(api);
  show(2, log, api, { log });
}
// 3. Bọc thêm thử lại; API lỗi lần đầu.
{
  const api = new HttpRateSource(1);
  const log = new LoggingSource(api);
  const retry = new RetrySource(log);
  show(3, retry, api, { note: ", API lỗi lần đầu", log, retry });
}
// 4. Bọc thêm cache ngoài cùng; gọi hai lần cùng một cặp tiền.
{
  const api = new HttpRateSource();
  const log = new LoggingSource(api);
  const retry = new RetrySource(log);
  const cache = new CachingSource(retry);
  show(4, cache, api, { calls: 2, note: ", gọi 2 lần", log, retry, cache });
}

Khi nào dùng

  • Khi cần thêm những việc bao quanh một lời gọi mà không đụng vào lớp gốc, như log, đo thời gian, cache, thử lại, giới hạn tần suất, kiểm quyền, nén hay mã hoá.
  • Khi những việc đó cần bật tắt hoặc kết hợp theo nhiều kiểu, tuỳ nơi dùng hoặc tuỳ cấu hình lúc chạy.
  • Khi không sửa được lớp gốc, chẳng hạn một thư viện hay SDK của bên thứ ba, nhưng vẫn cần thêm hành vi cho nó.
  • Thật ra bạn đã gặp pattern này nhiều lần: luồng I/O của Java với BufferedInputStream bọc FileInputStream, middleware bọc HTTP client, hay functools.lru_cache và các decorator hàm của Python.

Khi nào không nên

  • Khi chỉ cần thêm một việc, ở một nơi, và sẽ không đổi. Viết thẳng vào chỗ gọi đơn giản hơn nhiều.
  • Khi interface có rất nhiều phương thức. Lớp bọc nào cũng phải chuyển tiếp từng phương thức, kể cả những phương thức nó không quan tâm.
  • Khi code gọi cần biết chính xác lớp cụ thể, ví dụ dùng isinstance hay ép kiểu, vì bọc vào là mất kiểu gốc.
  • Khi có quá nhiều lớp mỏng chồng lên nhau. Stack trace sẽ dài, và lần ra lỗi rất mệt.

Dễ nhầm với

  • Adapter đổi một interface sang interface khác, còn Decorator giữ nguyên interface và thêm hành vi.
  • Proxy cũng giữ nguyên interface và đứng trước đối tượng thật, nhưng mục đích là kiểm soát truy cập, như tải lười, kiểm quyền hay gọi từ xa. Proxy thường tự quản lý đối tượng thật, còn decorator được bọc chồng tuỳ ý từ bên ngoài. Một lớp cache có thể hiểu theo cả hai cách.
  • Chain of Responsibility cũng chuyền lời gọi qua từng mắt, nhưng mỗi mắt tự quyết định xử lý hay chuyển tiếp. Decorator thì gần như luôn chuyển tiếp xuống, trừ trường hợp như cache khi nó đã có sẵn câu trả lời.
  • Decorator của Python, tức cú pháp @, là cùng một ý tưởng áp dụng cho hàm: bọc một hàm bằng một hàm khác có cùng chữ ký.

Ghi chú khi triển khai

  • Thứ tự bọc có ý nghĩa. Nếu cache nằm ngoài cùng, lần gọi trúng cache sẽ không đi qua thử lại hay log. Nếu log nằm trong thử lại, mỗi lần thử được ghi một dòng, còn đặt log ở ngoài thì cả lời gọi chỉ có một dòng.
  • Mỗi lớp bọc chỉ nên làm một việc. Nó gọi xuống đúng một lần, trừ thử lại và cache, để khi đổi thứ tự thì kết quả vẫn đúng.
  • Hãy lắp các lớp ở một chỗ duy nhất. Dựng chồng decorator trong hàm khởi tạo hoặc container DI, đừng rải ra khắp những nơi dùng.
  • Cache và thử lại khi chạy thật cần thêm cấu hình. Cache cần thời hạn hết hạn, thường gọi là TTL, và giới hạn kích thước. Thử lại cần chờ tăng dần giữa các lần, và chỉ thử lại lỗi thoáng qua chứ không thử lại lỗi sai tham số.
  • Interface lớn thì nên có một lớp bọc gốc. Lớp này chuyển tiếp mọi phương thức, rồi mỗi decorator chỉ ghi đè phương thức mà nó cần thêm hành vi.

Kiểm tra nhanh

Sáu câu hỏi ngắn để xem bạn đã nắm Decorator tới đâu. Chọn một đáp án, lời giải thích sẽ hiện ngay bên dưới.

  1. Câu 1 Một lớp gửi SMS đang chạy ổn. Giờ bạn cần ghi log và giới hạn số tin gửi mỗi phút, nhưng chỉ khi chạy trên production. Cách nào hợp lý nhất?

    Decorator cho phép mỗi việc thêm vào là một lớp bọc riêng, chỉ lắp vào ở nơi cần, nên lớp gốc không phải sửa. Thêm cờ hay tạo lớp con đều làm lớp gốc phình ra, và số lớp con sẽ tăng theo mọi tổ hợp tính năng.

  2. Câu 2 Trong ví dụ tỷ giá, lớp nào đóng vai Concrete component?

    HttpRateSource là phần lõi thật, chỉ làm đúng một việc là gọi API tỷ giá. RateSource là interface chung, còn CachingSource và LoggingSource là các decorator bọc bên ngoài.

  3. Câu 3 Ở bước 4, CachingSource bọc ngoài cùng và ta gọi get_rate("USD/VND") hai lần. API thật bị gọi bao nhiêu lần?

    Lời gọi đầu đi xuống tới API, và CachingSource nhớ lại kết quả 25.380 ₫. Lời gọi thứ hai dừng ngay ở lớp cache ngoài cùng, nên bộ đếm API vẫn là 1 và LOG cũng chỉ có một dòng.

  4. Câu 4 Ở bước 3, API lỗi ở lần đầu rồi thành công ở lần thử thứ hai. Vì sao LOG ghi hai dòng chứ không phải một?

    Chồng lớp ở bước này là RetrySource bọc ngoài LoggingSource, nên mỗi lần RETRY gọi xuống là một lần đi qua LOG, được một dòng lỗi và một dòng thành công. Nếu đặt LOG ở ngoài RETRY, cả lời gọi chỉ có một dòng.

  5. Câu 5 Trường hợp nào Decorator dễ gây rắc rối hơn là giúp ích?

    Bọc một đối tượng vào decorator là mất kiểu gốc của nó, nên code dựa vào isinstance hay ép kiểu sẽ chạy sai. Ba trường hợp còn lại lại chính là chỗ Decorator phát huy tác dụng.

  6. Câu 6 Decorator và Proxy đều giữ nguyên interface. Khác biệt chính giữa chúng là gì?

    Cả hai đều đứng trước một đối tượng có cùng interface. Proxy lo chuyện ai được dùng và dùng lúc nào, như tải lười hay kiểm quyền, còn decorator xếp chồng thêm hành vi. Đổi interface là việc của Adapter.

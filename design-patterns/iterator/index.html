Behavioral pattern

Iterator

Iterator cho phép bạn đi qua từng phần tử của một tập hợp mà không cần biết tập hợp ấy được lưu ra sao, dù nó nằm sẵn trong bộ nhớ, chia thành từng trang trên một API hay đọc dần từ một file lớn. Chỗ gọi chỉ việc xin phần tử kế tiếp, còn chuyện lấy nó ở đâu là việc của iterator.

Bài toán

Hệ thống cần đọc danh sách đơn hàng từ API của một đối tác. API trả về mỗi lần một trang bốn đơn, kèm một cursor để lấy trang sau, và trang cuối thì không có cursor nào. Hiện có 10 đơn nằm trong 3 trang như sau:

TrangCursor gửi lênĐơn hàngCursor của trang sau
1không cóDH-001, DH-002, DH-003, DH-004c2
2c2DH-005, DH-006, DH-007, DH-008c3
3c3DH-009, DH-010không có, đây là trang cuối

Nhiều nơi trong hệ thống cần danh sách này. Báo cáo doanh thu phải đọc hết, còn màn hình tìm kiếm chỉ cần đọc tới đơn đầu tiên trên 2.000.000 ₫ rồi dừng. Ta muốn không nơi nào phải bận tâm tới trang hay cursor, và không trang nào bị tải khi chưa cần.

Khi chưa có Iterator

Cách làm thường thấy là chỗ nào cần đơn hàng thì tự viết vòng lặp gọi API, tự giữ cursor và tự quyết lúc nào dừng:

// Trước khi có Iterator: chỗ nào cần danh sách đơn hàng cũng tự viết vòng lặp phân trang.
// Chạy: node before.ts   (Node 22.18 trở lên chạy thẳng TypeScript)

interface Page {
  items: [string, number][];
  nextCursor: string | null;
}

const PAGES: Record<string, Page> = {
  start: { items: [["DH-001", 450_000], ["DH-002", 1_250_000], ["DH-003", 320_000], ["DH-004", 860_000]], nextCursor: "c2" },
  c2: { items: [["DH-005", 1_900_000], ["DH-006", 2_400_000], ["DH-007", 560_000], ["DH-008", 1_100_000]], nextCursor: "c3" },
  c3: { items: [["DH-009", 3_150_000], ["DH-010", 780_000]], nextCursor: null },
};

// API giả: trả từng trang đơn hàng theo cursor và đếm số lần bị gọi.
class OrderApi {
  calls = 0;

  listOrders(cursor: string | null = null): Page {
    this.calls += 1;
    return PAGES[cursor ?? "start"];
  }
}

const vnd = (n: number) => String(n).replace(/\B(?=(\d{3})+(?!\d))/g, ".");

// Báo cáo doanh thu tự lo chuyện phân trang: giữ cursor, gọi tiếp, biết lúc nào dừng.
function revenue(api: OrderApi): number {
  let total = 0;
  let cursor: string | null = null;
  while (true) {
    const page = api.listOrders(cursor);
    total += page.items.reduce((sum, [, amount]) => sum + amount, 0);
    cursor = page.nextCursor;
    if (cursor === null) break;
  }
  return total;
}

// Màn hình đếm đơn chép lại vòng lặp ấy, nhưng điều kiện dừng đặt sai chỗ:
// nó thoát ngay khi thấy trang cuối, trước khi kịp đếm các đơn trong trang đó.
function countOrders(api: OrderApi): number {
  let count = 0;
  let page = api.listOrders();
  while (page.nextCursor !== null) {
    count += page.items.length;
    page = api.listOrders(page.nextCursor);
  }
  return count;
}

Chạy thử, ta được kết quả này.

Doanh thu: 12.770.000 ₫ sau 3 lần gọi API
Số đơn: 8, đúng ra phải là 10
  • Logic phân trang bị chép ra khắp nơi. Mỗi chỗ gọi đều phải biết API trả cursor thế nào và trang cuối trông ra sao, dù việc của nó chỉ là xử lý đơn hàng.
  • Chép lại thì dễ chép sai. Hàm đếm đơn đặt điều kiện dừng sai chỗ nên bỏ sót trang cuối, đếm ra 8 thay vì 10, và chẳng có lỗi nào được báo ra.
  • Muốn dừng sớm thì mỗi nơi lại tự xoay xở. Vòng lặp nào cần ngừng khi đã tìm thấy thứ mình cần cũng phải tự thêm cờ và điều kiện của riêng nó.
  • Đối tác đổi API là phải sửa mọi nơi. Khi họ chuyển từ cursor sang số trang, mọi vòng lặp đã chép đều phải viết lại.

Lời giải

Ta tách việc duyệt ra một đối tượng riêng, gọi là Iterator. Nó nhớ trang đang cầm và vị trí trong trang, và mỗi lần được gọi next() thì trả về đúng một đơn. Chỉ khi trang trong tay đã dùng hết, nó mới gọi API lấy trang sau bằng cursor. Khi cả trang cuối cũng hết, nó báo cho vòng lặp biết để dừng.

Tập đơn hàng đóng vai Aggregate. Mỗi khi có một vòng lặp mới, nó tạo một iterator mới, nên hai vòng lặp không giẫm lên vị trí của nhau. Python gọi hai phương thức này là __iter__ và __next__, còn TypeScript dùng [Symbol.iterator]() và next(), nhờ vậy vòng for quen thuộc dùng được ngay.

"""Iterator: duyệt đơn hàng của một API phân trang mà chỗ gọi không phải biết gì về trang hay cursor.

Chạy: python3 iterator.py
"""
from dataclasses import dataclass

PAGES = {
    None: {"items": [("DH-001", 450_000), ("DH-002", 1_250_000), ("DH-003", 320_000), ("DH-004", 860_000)], "next_cursor": "c2"},
    "c2": {"items": [("DH-005", 1_900_000), ("DH-006", 2_400_000), ("DH-007", 560_000), ("DH-008", 1_100_000)], "next_cursor": "c3"},
    "c3": {"items": [("DH-009", 3_150_000), ("DH-010", 780_000)], "next_cursor": None},
}


@dataclass(frozen=True)
class Order:
    code: str
    total: int


def vnd(n: int) -> str:
    return f"{n:,}".replace(",", ".")


class OrderApi:
    """API giả: trả từng trang đơn hàng theo cursor, đếm và in ra mỗi lần bị gọi."""

    def __init__(self) -> None:
        self.calls = 0

    def list_orders(self, cursor: str | None = None) -> dict:
        self.calls += 1
        page = PAGES[cursor]
        tail = ", đây là trang cuối" if page["next_cursor"] is None else ""
        print(f"  gọi API lần {self.calls}, cursor {cursor or 'đầu'}: nhận {len(page['items'])} đơn{tail}")
        return page


class OrderIterator:
    """Iterator: nhớ trang đang cầm và vị trí trong trang, chỉ gọi API khi trang ấy đã dùng hết."""

    def __init__(self, api: OrderApi) -> None:
        self._api = api
        self._items: list = []
        self._pos = 0
        self._cursor: str | None = None
        self._started = False

    def __iter__(self) -> "OrderIterator":
        return self

    def __next__(self) -> Order:
        while self._pos == len(self._items):
            if self._started and self._cursor is None:
                raise StopIteration  # trang cuối đã dùng hết: báo cho vòng for dừng lại
            page = self._api.list_orders(self._cursor)
            self._started = True
            self._items, self._pos = page["items"], 0
            self._cursor = page["next_cursor"]
        code, total = self._items[self._pos]
        self._pos += 1
        return Order(code, total)


class OrderList:
    """Aggregate: tập đơn hàng nằm sau API. Mỗi vòng lặp nhận một iterator mới của riêng nó."""

    def __init__(self, api: OrderApi) -> None:
        self._api = api

    def __iter__(self) -> OrderIterator:
        return OrderIterator(self._api)


# Client chỉ viết vòng for. Không có cursor, không có số trang, không có điều kiện dừng nào.
print("Duyệt hết danh sách:")
api = OrderApi()

print(f"  {len(orders)} đơn, tổng {vnd(sum(order.total for order in orders))} ₫, {api.calls} lần gọi API")

// Iterator: duyệt đơn hàng của một API phân trang mà chỗ gọi không phải biết gì về trang hay cursor.
// Chạy: node iterator.ts   (Node 22.18 trở lên chạy thẳng TypeScript)

interface Page {
  items: [string, number][];
  nextCursor: string | null;
}

const PAGES: Record<string, Page> = {
  start: { items: [["DH-001", 450_000], ["DH-002", 1_250_000], ["DH-003", 320_000], ["DH-004", 860_000]], nextCursor: "c2" },
  c2: { items: [["DH-005", 1_900_000], ["DH-006", 2_400_000], ["DH-007", 560_000], ["DH-008", 1_100_000]], nextCursor: "c3" },
  c3: { items: [["DH-009", 3_150_000], ["DH-010", 780_000]], nextCursor: null },
};

interface Order {
  code: string;
  total: number;
}

const vnd = (n: number) => String(n).replace(/\B(?=(\d{3})+(?!\d))/g, ".");

// API giả: trả từng trang đơn hàng theo cursor, đếm và in ra mỗi lần bị gọi.
class OrderApi {
  calls = 0;

  listOrders(cursor: string | null = null): Page {
    this.calls += 1;
    const page = PAGES[cursor ?? "start"];
    const tail = page.nextCursor === null ? ", đây là trang cuối" : "";
    console.log(`  gọi API lần ${this.calls}, cursor ${cursor ?? "đầu"}: nhận ${page.items.length} đơn${tail}`);
    return page;
  }
}

// Iterator: nhớ trang đang cầm và vị trí trong trang, chỉ gọi API khi trang ấy đã dùng hết.
class OrderIterator implements Iterator<Order> {
  private readonly api: OrderApi;
  private items: [string, number][] = [];
  private pos = 0;
  private cursor: string | null = null;
  private started = false;

  constructor(api: OrderApi) {
    this.api = api;
  }

  next(): IteratorResult<Order> {
    while (this.pos === this.items.length) {
      // Trang cuối đã dùng hết: báo cho vòng for dừng lại.
      if (this.started && this.cursor === null) return { done: true, value: undefined };
      const page = this.api.listOrders(this.cursor);
      this.started = true;
      this.items = page.items;
      this.pos = 0;
      this.cursor = page.nextCursor;
    }
    const [code, total] = this.items[this.pos];
    this.pos += 1;
    return { done: false, value: { code, total } };
  }
}

// Aggregate: tập đơn hàng nằm sau API. Mỗi vòng lặp nhận một iterator mới của riêng nó.
class OrderList implements Iterable<Order> {
  private readonly api: OrderApi;

  constructor(api: OrderApi) {
    this.api = api;
  }

  [Symbol.iterator](): OrderIterator {
    return new OrderIterator(this.api);
  }
}

// Client chỉ viết vòng for. Không có cursor, không có số trang, không có điều kiện dừng nào.
console.log("Duyệt hết danh sách:");
let api = new OrderApi();
const orders = [...new OrderList(api)];
const sum = orders.reduce((s, order) => s + order.total, 0);
console.log(`  ${orders.length} đơn, tổng ${vnd(sum)} ₫, ${api.calls} lần gọi API`);

console.log("Tìm đơn đầu tiên trên 2.000.000 ₫:");
api = new OrderApi();
let seen = 0;
for (const order of new OrderList(api)) {
  seen += 1;
  if (order.total > 2_000_000) {
    console.log(`  thấy ${order.code} (${vnd(order.total)} ₫) ở đơn thứ ${seen} rồi dừng vòng lặp`);
    break;
  }
}
console.log(`  ${api.calls} lần gọi API, trang thứ ba không bao giờ được tải`);

Khi nào dùng

  • Dữ liệu đến dần hoặc quá lớn để nạp hết vào bộ nhớ, như API phân trang, kết quả truy vấn đọc theo lô hay một file log hàng triệu dòng.
  • Bạn muốn giấu cấu trúc bên trong của một tập hợp, có thể là cây, đồ thị hay nhiều nguồn ghép lại, và chỉ cho bên ngoài một cách duyệt duy nhất.
  • Một tập hợp cần nhiều cách duyệt khác nhau, chẳng hạn theo thời gian hay theo từng khách hàng, mà bạn không muốn nhồi hết vào lớp tập hợp.

Khi nào không nên

  • Khi dữ liệu nhỏ và đã nằm sẵn trong một list. Ngôn ngữ đã có iterator cho list, viết thêm một lớp chỉ làm code dài hơn.
  • Khi bạn cần truy cập ngẫu nhiên, biết trước tổng số phần tử hay đọc đi đọc lại nhiều lần. Iterator chỉ đi tới, nên những việc ấy cần một danh sách thật hoặc một API khác.
  • Khi dữ liệu có thể thay đổi giữa chừng mà bạn cần một ảnh chụp nhất quán. Iterator lười thấy dữ liệu ở thời điểm nó lấy từng trang, chứ không phải lúc vòng lặp bắt đầu.

Dễ nhầm với

  • Composite hay đi cùng Iterator, vì iterator là cách gọn gàng để duyệt một cây composite. Composite lo hình dạng của cây, còn Iterator lo thứ tự đi qua nó.
  • Visitor cũng đi qua một tập đối tượng, nhưng nó mang theo một thao tác để làm trên từng loại phần tử. Iterator chỉ đưa từng phần tử ra, còn làm gì với phần tử đó là việc của chỗ gọi.
  • Generator trong Python hay TypeScript không phải một pattern khác. Đó là cách ngôn ngữ giúp bạn viết Iterator ngắn hơn, vì hàm có yield tự nhớ mình đang dừng ở đâu.

Ghi chú khi triển khai

  • Mỗi vòng lặp nên có một iterator riêng. Nếu __iter__ trả về một đối tượng dùng chung đang giữ vị trí, hai vòng lặp sẽ giẫm lên nhau và vòng sau có thể chẳng nhận được đơn nào.
  • Trong Python, generator viết ngắn hơn nhiều. Cả lớp OrderIterator có thể thay bằng một hàm với vòng while và yield, còn việc nhớ vị trí và báo dừng thì Python tự lo.
  • Với API thật, hãy dùng iterator bất đồng bộ. Python có async for với __anext__, TypeScript có for await với Symbol.asyncIterator, để việc chờ mạng không chặn cả chương trình.
  • Hãy dọn dẹp khi vòng lặp dừng sớm. Nếu iterator giữ kết nối hay file, hãy đóng chúng khi gặp break, chẳng hạn bằng try/finally trong generator hoặc phương thức return() trong TypeScript.

Kiểm tra nhanh

Sáu câu hỏi ngắn để xem bạn đã nắm Iterator tới đâu. Chọn một đáp án, lời giải thích sẽ hiện ngay bên dưới.

  1. Câu 1 Ứng dụng của bạn cần xử lý một file log 20 GB, mỗi dòng là một sự kiện, trên một máy chỉ có 2 GB RAM. Cách nào hợp lý nhất?

    Iterator chỉ lấy phần tử kế tiếp khi vòng lặp cần, nên bộ nhớ dùng không phụ thuộc vào kích thước file. Đọc hết vào một list thì cần ít nhất 20 GB, còn chia tay hay nâng RAM chỉ là chữa cháy.

  2. Câu 2 Ở bước “Sang trang 2”, khi trả về DH-005 thì iterator đã gọi API bao nhiêu lần?

    Iterator gọi API một lần cho trang 1, rồi chỉ gọi lần thứ hai khi đơn thứ năm được xin, lúc ấy trang 3 vẫn chưa được tải. Nó cũng không gọi API ở mỗi lần next(), vì bốn đơn của một trang được trả từ chính trang đang cầm.

  3. Câu 3 Trong code ví dụ, lớp nào đóng vai Aggregate?

    OrderList là tập đơn hàng mà vòng lặp duyệt qua, và mỗi lần __iter__ được gọi nó tạo một OrderIterator mới. OrderIterator là Iterator, Order là phần tử, còn OrderApi chỉ là nguồn dữ liệu nằm phía sau.

  4. Câu 4 Bạn sửa OrderList để __iter__ luôn trả về cùng một iterator, tạo sẵn trong constructor. Chuyện gì sẽ xảy ra khi duyệt nó hai lần?

    Iterator giữ vị trí hiện tại. Nếu mọi vòng lặp dùng chung một iterator, vòng sau sẽ đi tiếp từ chỗ vòng trước bỏ dở, và một iterator đã cạn thì không trả thêm gì nữa. Python chỉ gọi __iter__, còn tạo mới hay không là do bạn viết.

  5. Câu 5 Iterator khác Visitor ở điểm nào?

    Iterator lo thứ tự đi qua tập hợp và để chỗ gọi tự quyết làm gì với mỗi phần tử. Visitor thì gói sẵn thao tác, chẳng hạn tính thuế cho từng loại sản phẩm. Iterator cũng không chỉ dành cho list, vì cây hay API phân trang đều duyệt được bằng nó.

  6. Câu 6 Vòng lặp tìm đơn trên 2.000.000 ₫ gặp break ở DH-006. Nếu iterator đang giữ một kết nối tới cơ sở dữ liệu thay vì gọi API, bạn cần lưu ý điều gì?

    Khi gặp break, iterator chỉ đơn giản là không được gọi tiếp, nên kết nối nó giữ vẫn mở nếu bạn không dọn. Generator chạy khối finally khi bị đóng, còn TypeScript gọi phương thức return() của iterator. Đọc nốt chỉ để kết thúc thì phí công, giống như tải trang thứ ba mà không ai cần.

Behavioral pattern

Template Method

Template Method đặt khung của một thuật toán vào một hàm ở lớp cha: các bước chạy theo thứ tự nào do lớp cha quyết định và không đổi. Lớp con chỉ viết những bước được để trống (bước bắt buộc) và, nếu cần, ghi đè vài bước tuỳ chọn (hook).

Bài toán

Hệ thống bán hàng cần xuất báo cáo đơn hàng trong ngày ra nhiều định dạng: CSV cho kế toán mở bằng bảng tính, JSON Lines cho kho dữ liệu, và một file độ rộng cố định gửi ngân hàng. Định dạng nào cũng phải đi qua cùng các bước:

  1. Đọc đơn hàng trong ngày (ví dụ có 6 đơn).
  2. Lọc bỏ đơn đã huỷ (2 đơn), chỉ xuất 4 đơn đã thanh toán.
  3. Định dạng từng dòng, có thể kèm dòng đầu (header) và dòng cuối (footer).
  4. Ghi file và báo số dòng đã ghi.

Chỉ bước định dạng là khác nhau. Đọc, lọc và ghi phải giống hệt nhau ở mọi định dạng, nếu không ba file sẽ cho ba con số khác nhau.

Khi chưa có Template Method

Cách làm thường gặp là viết hàm export cho định dạng đầu tiên, rồi chép ra và sửa cho định dạng tiếp theo:

// Khi chưa có Template Method: mỗi định dạng một hàm export, chép gần giống nhau.
type Order = { id: string; amount: number; status: string };

const ORDERS: Order[] = [
  { id: "DH-101", amount: 1250000, status: "paid" },
  { id: "DH-102", amount: 860000, status: "cancelled" },
  { id: "DH-103", amount: 2400000, status: "paid" },
  { id: "DH-104", amount: 540000, status: "paid" },
  { id: "DH-105", amount: 1100000, status: "cancelled" },
  { id: "DH-106", amount: 375000, status: "paid" },
];

const vnd = (n: number) => n.toLocaleString("vi-VN");
const sum = (rows: Order[]) => rows.reduce((total, o) => total + o.amount, 0);

function exportCsv(orders: Order[]): string[] {
  const rows = orders.filter((o) => o.status !== "cancelled");
  const lines = ["ma_don,so_tien", ...rows.map((o) => `${o.id},${o.amount}`)];
  console.log(`report.csv: ${rows.length} đơn, tổng ${vnd(sum(rows))} ₫`);
  return lines;
}

function exportJsonl(orders: Order[]): string[] {
  const rows = orders; // chép từ exportCsv rồi sửa, quên mất bước lọc đơn huỷ
  const lines = rows.map((o) => JSON.stringify({ ma_don: o.id, so_tien: o.amount }));
  console.log(`report.jsonl: ${rows.length} đơn, tổng ${vnd(sum(rows))} ₫`);
  return lines;
}

exportCsv(ORDERS);
exportJsonl(ORDERS);

Kết quả khi chạy:

report.csv: 4 đơn, tổng 4.565.000 ₫
report.jsonl: 6 đơn, tổng 6.525.000 ₫
  • Hai bản chép trôi xa nhau. Bản JSON Lines quên bước lọc, nên xuất cả 2 đơn đã huỷ: 6 đơn, 6.525.000 ₫ thay vì 4 đơn, 4.565.000 ₫. Không có lỗi nào được báo, chỉ có số sai.
  • Sửa một quy tắc là sửa N chỗ. Thêm điều kiện "bỏ đơn thử nghiệm" phải nhớ sửa mọi hàm export; hàm nào sót thì sai.
  • Thứ tự các bước không được giữ. Không có gì ngăn một hàm định dạng trước rồi mới lọc, hay ghi file trước khi tính số dòng.
  • Phần khác nhau bị chìm. Đọc hàm phải tự dò xem dòng nào là logic chung, dòng nào là của riêng định dạng đó.

Lời giải

Đưa khung vào một hàm export() ở lớp cha ReportExporter (template method). Nó gọi các bước theo đúng thứ tự: đọc, lọc, header(), format_row() cho từng đơn, footer(), ghi. Đọc, lọc và ghi được viết một lần ở lớp cha. format_row() là bước bắt buộc (abstract): lớp con nào cũng phải viết. header() và footer() là hook: lớp cha cho sẵn bản mặc định không làm gì, lớp con ghi đè khi định dạng của nó cần.

template-method.pypython3 template-method.py
"""Template Method: một khung export cố định, lớp con chỉ viết phần định dạng.

Chạy: python3 template-method.py
"""
import json
from abc import ABC, abstractmethod
from dataclasses import dataclass


@dataclass(frozen=True)
class Order:
    id: str
    amount: int  # VND
    status: str  # "paid" hoặc "cancelled"


ORDERS = [
    Order("DH-101", 1250000, "paid"),
    Order("DH-102", 860000, "cancelled"),
    Order("DH-103", 2400000, "paid"),
    Order("DH-104", 540000, "paid"),
    Order("DH-105", 1100000, "cancelled"),
    Order("DH-106", 375000, "paid"),
]


def vnd(n: int) -> str:
    return f"{n:,}".replace(",", ".")


class ReportExporter(ABC):
    extension = "txt"

    # Template method: thứ tự các bước cố định. Lớp con không ghi đè hàm này.
    def export(self) -> list[str]:
        orders = self.read_orders()
        rows = self.keep_valid(orders)
        lines = []
        header = self.header()
        if header is not None:
            lines.append(header)
        lines.extend(self.format_row(order) for order in rows)
        footer = self.footer(rows)
        if footer is not None:
            lines.append(footer)
        self.write(lines, orders, rows)
        return lines

    # Các bước dùng chung: viết một lần ở lớp cha.
    def read_orders(self) -> list[Order]:
        return ORDERS  # thực tế: truy vấn cơ sở dữ liệu

    def keep_valid(self, orders: list[Order]) -> list[Order]:
        return [order for order in orders if order.status != "cancelled"]

    def write(self, lines: list[str], orders: list[Order], rows: list[Order]) -> None:
        print(f"== report.{self.extension} ==")
        print("\n".join(lines))
        total = sum(order.amount for order in rows)
        print(f"-> đọc {len(orders)} đơn, bỏ {len(orders) - len(rows)} đơn huỷ, ghi {len(lines)} dòng, tổng {vnd(total)} ₫\n")

    # Bước bắt buộc: lớp con phải viết.
    @abstractmethod
    def format_row(self, order: Order) -> str: ...

    # Hook: mặc định không làm gì, lớp con ghi đè khi cần.
    def header(self) -> str | None:
        return None

    def footer(self, rows: list[Order]) -> str | None:
        return None


class CsvExporter(ReportExporter):
    extension = "csv"

    def header(self) -> str:
        return "ma_don,so_tien"

    def format_row(self, order: Order) -> str:
        return f"{order.id},{order.amount}"


class JsonLinesExporter(ReportExporter):
    extension = "jsonl"

    def format_row(self, order: Order) -> str:
        return json.dumps({"ma_don": order.id, "so_tien": order.amount}, separators=(",", ":"))


class FixedWidthExporter(ReportExporter):
    """File độ rộng cố định, kiểu file gửi ngân hàng: bản ghi đầu, chi tiết, bản ghi cuối."""

    def header(self) -> str:
        return "H20261030BAOCAO"

    def format_row(self, order: Order) -> str:
        return f"D{order.id:<8}{order.amount:012d}"

    def footer(self, rows: list[Order]) -> str:
        return f"T{len(rows):06d}{sum(order.amount for order in rows):012d}"


if __name__ == "__main__":
    for exporter in (CsvExporter(), JsonLinesExporter(), FixedWidthExporter()):
        exporter.export()

// Template Method: một khung export cố định, lớp con chỉ viết phần định dạng.
// Chạy: node template-method.ts   (Node 22.18 trở lên chạy thẳng TypeScript)

interface Order {
  id: string;
  amount: number; // VND
  status: "paid" | "cancelled";
}

const ORDERS: Order[] = [
  { id: "DH-101", amount: 1250000, status: "paid" },
  { id: "DH-102", amount: 860000, status: "cancelled" },
  { id: "DH-103", amount: 2400000, status: "paid" },
  { id: "DH-104", amount: 540000, status: "paid" },
  { id: "DH-105", amount: 1100000, status: "cancelled" },
  { id: "DH-106", amount: 375000, status: "paid" },
];

const vnd = (n: number) => n.toLocaleString("vi-VN");
const sum = (rows: Order[]) => rows.reduce((total, order) => total + order.amount, 0);

abstract class ReportExporter {
  protected extension = "txt";

  // Template method: thứ tự các bước cố định. Lớp con không ghi đè hàm này.
  export(): string[] {
    const orders = this.readOrders();
    const rows = this.keepValid(orders);
    const lines: string[] = [];
    const header = this.header();
    if (header !== null) lines.push(header);
    for (const order of rows) lines.push(this.formatRow(order));
    const footer = this.footer(rows);
    if (footer !== null) lines.push(footer);
    this.write(lines, orders, rows);
    return lines;
  }

  // Các bước dùng chung: viết một lần ở lớp cha.
  protected readOrders(): Order[] {
    return ORDERS; // thực tế: truy vấn cơ sở dữ liệu
  }

  protected keepValid(orders: Order[]): Order[] {
    return orders.filter((order) => order.status !== "cancelled");
  }

  protected write(lines: string[], orders: Order[], rows: Order[]): void {
    console.log(`== report.${this.extension} ==`);
    console.log(lines.join("\n"));
    console.log(`-> đọc ${orders.length} đơn, bỏ ${orders.length - rows.length} đơn huỷ, ghi ${lines.length} dòng, tổng ${vnd(sum(rows))} ₫\n`);
  }

  // Bước bắt buộc: lớp con phải viết.
  protected abstract formatRow(order: Order): string;

  // Hook: mặc định không làm gì, lớp con ghi đè khi cần.
  protected header(): string | null {
    return null;
  }

  protected footer(rows: Order[]): string | null {
    return null;
  }
}

class CsvExporter extends ReportExporter {
  protected extension = "csv";

  protected header(): string {
    return "ma_don,so_tien";
  }

  protected formatRow(order: Order): string {
    return `${order.id},${order.amount}`;
  }
}

class JsonLinesExporter extends ReportExporter {
  protected extension = "jsonl";

  protected formatRow(order: Order): string {
    return JSON.stringify({ ma_don: order.id, so_tien: order.amount });
  }
}

// File độ rộng cố định, kiểu file gửi ngân hàng: bản ghi đầu, chi tiết, bản ghi cuối.
class FixedWidthExporter extends ReportExporter {
  protected header(): string {
    return "H20261030BAOCAO";
  }

  protected formatRow(order: Order): string {
    return `D${order.id.padEnd(8)}${String(order.amount).padStart(12, "0")}`;
  }

  protected footer(rows: Order[]): string {
    return `T${String(rows.length).padStart(6, "0")}${String(sum(rows)).padStart(12, "0")}`;
  }
}

for (const exporter of [new CsvExporter(), new JsonLinesExporter(), new FixedWidthExporter()]) {
  exporter.export();
}

Khi nào dùng

  • Nhiều biến thể chạy cùng một quy trình nhiều bước và chỉ khác nhau ở vài bước: xuất báo cáo nhiều định dạng, nhập file từ nhiều nguồn (đọc, kiểm tra, chuyển đổi, lưu), gửi thông báo qua nhiều kênh với cùng bước chọn người nhận và ghi log.
  • Thứ tự các bước là một quy tắc cần giữ, ví dụ luôn kiểm tra quyền trước khi xử lý, hay luôn mở transaction rồi mới ghi.
  • Bạn viết framework hoặc lớp cơ sở để người khác mở rộng: họ chỉ điền vào chỗ trống mà không làm hỏng luồng chung. Nhiều framework dùng cách này cho vòng đời của request, job hay test (setUp, tearDown).

Khi nào không nên

  • Chỉ có một biến thể: một hàm bình thường là đủ.
  • Các biến thể khác nhau ở gần như mọi bước: khung chung chỉ còn là vỏ, và lớp con phải ghi đè hết.
  • Cần đổi phần khác nhau lúc chạy, hoặc ghép nhiều phần khác nhau với nhau: kế thừa cố định lựa chọn lúc viết code, nên Strategy (truyền object vào) linh hoạt hơn.
  • Cây kế thừa đã sâu: thêm một tầng lớp cha nữa làm code khó theo dõi hơn.

Dễ nhầm với

  • Strategy cũng tách phần thay đổi ra, nhưng bằng một object được truyền vào và có thể đổi lúc chạy, còn khung thì nằm ở object dùng nó. Template Method dùng kế thừa: phần thay đổi là các hàm lớp con ghi đè, và lớp cha giữ cả khung. Trong hình, nếu khuôn là một object cắm vào máy lúc chạy thì đó là Strategy; ở đây mỗi khuôn là một lớp con của chính cỗ máy.
  • Factory Method thường là một bước của Template Method: một bước trong khung tạo object, và lớp con quyết định tạo loại nào.
  • Hook trong framework (callback, event) giống hook ở đây về ý, nhưng thường được đăng ký từ ngoài vào thay vì ghi đè trong lớp con.

Ghi chú khi triển khai

  • Đừng để lớp con ghi đè template method. TypeScript và Python không có final thật cho phương thức (Python có typing.final cho công cụ kiểm tra kiểu), nên hãy đặt tên rõ và ghi chú; Java dùng final, C# để phương thức không virtual.
  • Phân biệt rõ bước bắt buộc (abstract, không có thân) và hook (có bản mặc định). Càng ít bước bắt buộc, viết lớp con mới càng dễ.
  • Giữ các bước dùng chung ở lớp cha protected hoặc đặt tên bắt đầu bằng _ nếu lớp con không nên gọi hay ghi đè chúng.
  • Test khung một lần bằng một lớp con giả (ví dụ một exporter ghi vào list), rồi test từng lớp con chỉ ở phần định dạng của nó.

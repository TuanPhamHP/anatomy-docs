Structural pattern

Composite

Composite ghép các object thành cây bộ phận và tổng thể, rồi cho phần lẻ và nhóm dùng chung một interface. Code bên ngoài gọi cùng một hàm cho một món đơn lẻ hay cả một thùng chứa thùng, và không cần biết bên trong lồng bao nhiêu tầng.

Bài toán

Kho đóng gói cần cân từng kiện trước khi giao, vì phí vận chuyển tính theo khối lượng. Một kiện có thể là:

KiệnBên trongKhối lượng
Bình gốm(một món hàng)1,5 kg
Hộp nhỏvỏ hộp 0,3 kg, bình giữ nhiệt 0,6 kg, hộp trà 0,5 kg1,4 kg
Thùng lớnvỏ thùng 0,9 kg, một hộp nhỏ như trên, sách 1,2 kg, bình gốm 1,5 kg5,0 kg

Hộp có thể nằm trong thùng, thùng có thể nằm trong thùng lớn hơn. Ngoài khối lượng, kho còn cần in danh sách đóng gói, đếm số món, tính giá trị khai báo: thao tác nào cũng phải đi hết cây kiện hàng.

Khi chưa có Composite

Dữ liệu là các dict có trường kind, và hàm cân tự hỏi từng thứ là món hàng hay hộp. Hàm này được viết khi hộp chỉ chứa món hàng:

before.pypython3 before.py
"""Khi chưa có Composite: code cân phải tự hỏi từng thứ là món hàng hay hộp."""


def kg(grams: int) -> str:
    return f"{grams / 1000:.1f} kg".replace(".", ",")


def weigh(parcel: dict) -> int:
    if parcel["kind"] == "item":
        return parcel["grams"]
    if parcel["kind"] == "box":
        total = parcel["tare"]
        for child in parcel["contents"]:
            # Viết khi hộp chỉ chứa món hàng. Hộp con không có "grams" nên bị tính là 0.
            total += child.get("grams", 0)
        return total
    raise ValueError(f"Không biết cân loại {parcel['kind']}")


def small_box() -> dict:
    return {"kind": "box", "name": "Hộp nhỏ", "tare": 300, "contents": [
        {"kind": "item", "name": "Bình giữ nhiệt", "grams": 600},
        {"kind": "item", "name": "Hộp trà", "grams": 500},
    ]}


if __name__ == "__main__":
    vase = {"kind": "item", "name": "Bình gốm", "grams": 1500}
    crate = {"kind": "box", "name": "Thùng lớn", "tare": 900, "contents": [
        small_box(),
        {"kind": "item", "name": "Sách", "grams": 1200},
        {"kind": "item", "name": "Bình gốm", "grams": 1500},
    ]}
    for parcel in (vase, small_box(), crate):
        print(f"{parcel['name']}: {kg(weigh(parcel))}")

// Khi chưa có Composite: code cân phải tự hỏi từng thứ là món hàng hay hộp.

type Node = { kind: "item"; name: string; grams: number } | { kind: "box"; name: string; tare: number; contents: Node[] };

const kg = (grams: number): string => `${(grams / 1000).toFixed(1).replace(".", ",")} kg`;

function weigh(parcel: Node): number {
  if (parcel.kind === "item") return parcel.grams;
  let total = parcel.tare;
  for (const child of parcel.contents) {
    // Viết khi hộp chỉ chứa món hàng. Hộp con không có "grams" nên bị tính là 0.
    total += child.kind === "item" ? child.grams : 0;
  }
  return total;
}

const smallBox = (): Node => ({
  kind: "box", name: "Hộp nhỏ", tare: 300, contents: [
    { kind: "item", name: "Bình giữ nhiệt", grams: 600 },
    { kind: "item", name: "Hộp trà", grams: 500 },
  ],
});

const vase: Node = { kind: "item", name: "Bình gốm", grams: 1500 };
const crate: Node = {
  kind: "box", name: "Thùng lớn", tare: 900, contents: [
    smallBox(),
    { kind: "item", name: "Sách", grams: 1200 },
    { kind: "item", name: "Bình gốm", grams: 1500 },
  ],
};

for (const parcel of [vase, smallBox(), crate]) console.log(`${parcel.name}: ${kg(weigh(parcel))}`);
Bình gốm: 1,5 kg
Hộp nhỏ: 1,4 kg
Thùng lớn: 3,6 kg

Thùng lớn ra 3,6 kg thay vì 5,0 kg: hộp nhỏ bên trong không có trường grams, nên bị cộng như 0 mà không ai báo lỗi.

  • Mỗi tầng lồng là một vòng lặp mới. Muốn cân đúng hộp trong thùng phải viết thêm một vòng lặp lồng, rồi lại thêm nữa khi có thùng trong thùng.
  • Kiểm tra loại rải khắp nơi. Hàm in danh sách đóng gói, hàm đếm món, hàm tính giá trị đều phải lặp lại cùng chuỗi if kind == ... và cùng cách đi cây.
  • Thêm loại mới là sửa mọi hàm. Thêm "túi quà" hay "pallet" nghĩa là tìm và sửa từng chỗ đang hỏi kind.
  • Sai mà không lỗi. Như ví dụ trên, thiếu một nhánh không làm chương trình dừng, chỉ cho ra con số sai.

Lời giải

Định nghĩa một interface chung cho mọi thứ đặt lên cân (Component): Parcel với weight() và lines(). Món hàng (Leaf) trả về khối lượng của chính nó. Hộp (Composite) cũng là một Parcel, giữ danh sách con và cộng vỏ hộp với weight() của từng con; con là món hàng hay hộp khác đều được, vì con nào cũng tự lo phần của mình. Cái cân (Client) chỉ gọi weight().

composite.pypython3 composite.py
"""Composite: một kiện hàng là một món, hoặc một hộp chứa món hàng và hộp khác.

Chạy: python3 composite.py
"""
from abc import ABC, abstractmethod


def kg(grams: int) -> str:
    return f"{grams / 1000:.1f} kg".replace(".", ",")


# Component: thứ gì đặt lên cân cũng trả lời được hai câu hỏi này.
class Parcel(ABC):
    def __init__(self, name: str) -> None:
        self.name = name

    @abstractmethod
    def weight(self) -> int: ...  # gam

    @abstractmethod
    def lines(self, depth: int = 0) -> list[str]: ...


# Leaf: một món hàng, không chứa gì bên trong.
class Item(Parcel):
    def __init__(self, name: str, grams: int) -> None:
        super().__init__(name)
        self.grams = grams

    def weight(self) -> int:
        return self.grams

    def lines(self, depth: int = 0) -> list[str]:
        return [f"{'  ' * depth}{self.name}: {kg(self.weight())}"]


# Composite: một hộp. Nó cũng là Parcel, và chứa các Parcel khác: món hàng hay hộp đều được.
class Box(Parcel):
    def __init__(self, name: str, tare: int) -> None:
        super().__init__(name)
        self.tare = tare  # khối lượng của vỏ hộp
        self.children: list[Parcel] = []

    def add(self, *parcels: Parcel) -> "Box":
        self.children.extend(parcels)
        return self

    def weight(self) -> int:
        return self.tare + sum(child.weight() for child in self.children)

    def lines(self, depth: int = 0) -> list[str]:
        head = f"{'  ' * depth}{self.name}: {kg(self.weight())} (vỏ {kg(self.tare)})"
        return [head] + [line for child in self.children for line in child.lines(depth + 1)]


# Client: cái cân. Nó chỉ gọi weight(), không hỏi thứ trên bàn cân là món hàng hay hộp.
def weigh(parcel: Parcel) -> str:
    return f"{parcel.name}: {kg(parcel.weight())}"


def small_box() -> Box:
    return Box("Hộp nhỏ", 300).add(Item("Bình giữ nhiệt", 600), Item("Hộp trà", 500))


if __name__ == "__main__":
    vase = Item("Bình gốm", 1500)
    small = small_box()
    crate = Box("Thùng lớn", 900).add(small_box(), Item("Sách", 1200), Item("Bình gốm", 1500))

    for parcel in (vase, small, crate):
        print(weigh(parcel))
    print()
    print("\n".join(crate.lines()))
composite.tsnode composite.ts
// Composite: một kiện hàng là một món, hoặc một hộp chứa món hàng và hộp khác.
// Chạy: node composite.ts

const kg = (grams: number): string => `${(grams / 1000).toFixed(1).replace(".", ",")} kg`;

// Component: thứ gì đặt lên cân cũng trả lời được hai câu hỏi này.
interface Parcel {
  readonly name: string;
  weight(): number; // gam
  lines(depth?: number): string[];
}

// Leaf: một món hàng, không chứa gì bên trong.
class Item implements Parcel {
  readonly name: string;
  private readonly grams: number;

  constructor(name: string, grams: number) {
    this.name = name;
    this.grams = grams;
  }

  weight(): number {
    return this.grams;
  }

  lines(depth = 0): string[] {
    return [`${"  ".repeat(depth)}${this.name}: ${kg(this.weight())}`];
  }
}

// Composite: một hộp. Nó cũng là Parcel, và chứa các Parcel khác: món hàng hay hộp đều được.
class Box implements Parcel {
  readonly name: string;
  private readonly tare: number; // khối lượng của vỏ hộp
  private readonly children: Parcel[] = [];

  constructor(name: string, tare: number) {
    this.name = name;
    this.tare = tare;
  }

  add(...parcels: Parcel[]): Box {
    this.children.push(...parcels);
    return this;
  }

  weight(): number {
    return this.tare + this.children.reduce((total, child) => total + child.weight(), 0);
  }

  lines(depth = 0): string[] {
    const head = `${"  ".repeat(depth)}${this.name}: ${kg(this.weight())} (vỏ ${kg(this.tare)})`;
    return [head, ...this.children.flatMap((child) => child.lines(depth + 1))];
  }
}

// Client: cái cân. Nó chỉ gọi weight(), không hỏi thứ trên bàn cân là món hàng hay hộp.
function weigh(parcel: Parcel): string {
  return `${parcel.name}: ${kg(parcel.weight())}`;
}

const smallBox = (): Box => new Box("Hộp nhỏ", 300).add(new Item("Bình giữ nhiệt", 600), new Item("Hộp trà", 500));

const vase = new Item("Bình gốm", 1500);
const small = smallBox();
const crate = new Box("Thùng lớn", 900).add(smallBox(), new Item("Sách", 1200), new Item("Bình gốm", 1500));

for (const parcel of [vase, small, crate]) console.log(weigh(parcel));
console.log();
console.log(crate.lines().join("\n"));

Danh sách đóng gói phía dưới là thao tác thứ hai trên cùng cây: mỗi nút tự in mình rồi nhờ các con in tiếp, không có dòng nào hỏi "đây là món hay hộp".

Khi nào dùng

  • Dữ liệu tự nhiên có dạng cây bộ phận và tổng thể: kiện hàng và thùng, danh mục và danh mục con, dự án gồm giai đoạn gồm công việc, menu gồm menu con, phòng ban gồm phòng ban, sản phẩm combo gồm sản phẩm và combo nhỏ hơn.
  • Code gọi muốn xử lý một phần tử lẻ và một nhóm theo cùng một cách: tính tổng, đếm, in, kiểm tra quyền, xuất ra cây JSON.
  • Độ sâu của cây không biết trước, hoặc người dùng tự lồng được (thư mục, nhóm quyền, bộ lọc gồm điều kiện AND/OR lồng nhau).

Khi nào không nên

  • Cấu trúc luôn phẳng, hoặc chỉ có đúng hai tầng cố định: một danh sách và một vòng lặp đọc dễ hơn.
  • Phần lẻ và nhóm thực ra cần những thao tác rất khác nhau. Ép chúng vào chung một interface sẽ đẻ ra các hàm "không hỗ trợ" ở một phía.
  • Cây rất sâu hoặc rất lớn và phải tính lại liên tục: đệ quy mỗi lần gọi có thể chậm, khi đó cần cache tổng ở từng nút hoặc tính trong database.

Dễ nhầm với

  • Decorator cũng bọc một object cùng interface, nhưng bọc đúng một object để thêm hành vi. Composite chứa nhiều con và gộp kết quả của chúng.
  • Iterator lo cách duyệt qua các phần tử. Composite lo cấu trúc cây; hai pattern hay đi cùng nhau khi cần duyệt cây theo nhiều kiểu.
  • Visitor thêm thao tác mới lên một cây có sẵn mà không sửa các lớp nút. Khi cây Composite cần quá nhiều thao tác, Visitor giúp tách chúng ra.
  • Chain of Responsibility cũng nối các object với nhau, nhưng thành một chuỗi để chuyển yêu cầu đi tiếp, không phải để gộp kết quả từ con lên cha.

Ghi chú khi triển khai

  • Chỉ đặt trên interface chung những thao tác có nghĩa cho cả lá và nhóm (weight(), lines()). add() chỉ có ở Box, nên không thể vô tình thêm con vào một món hàng.
  • Nhóm có thể đóng góp phần của chính nó, như vỏ hộp ở đây, chứ không chỉ cộng các con.
  • Không để một nút nằm trong chính nó hoặc trong con cháu của nó: đệ quy sẽ không bao giờ dừng. Khi người dùng tự lồng được (thư mục, nhóm quyền), kiểm tra vòng lặp lúc thêm con.
  • Trong database, cây thường lưu bằng parent_id; dựng lại cây object rồi gọi đệ quy, hoặc dùng truy vấn đệ quy (CTE) khi chỉ cần một con số tổng.
